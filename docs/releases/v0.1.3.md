# flink-sql-go v0.1.3 릴리스 노트

- 릴리스 버전: `v0.1.3`
- 지원 Apache Flink 버전: `1.20.4`
- 지원 SQL Gateway REST API: `v1`, `v2`, `v3`
- 기준 Go 버전: `1.26.5`
- 릴리스 예정일: 2026-07-27

## 개요

`v0.1.3`은 Flink 1.20.4 SQL Gateway에 statement를 제출할 때 기본
`ExecutionTimeout` 때문에 HTTP 500과 `ErrExecutionOutcomeUnknown`이 발생하던 호환성
문제를 수정한 patch release다.

기존 client는 기본 30초 실행 제한을 REST request의 양수 `executionTimeout`으로 전송했다.
그러나 Flink 1.20.4는 이 wire timeout을 구현하지 않았으며 양수 값이 들어오면 operation을
제출하기 전에 `UnsupportedOperationException`을 반환한다. client는 이 HTTP 500을 비멱등
요청의 안전한 오류 정책에 따라 `ExecutionOutcomeUnknownError`로 분류했다.

이번 릴리스는 `ExecutionTimeout`을 client-side context 제한으로만 적용하고 Flink 1.20.4가
지원하지 않는 REST field를 전송하지 않는다.


## 주요 변경사항

### Statement 실행 timeout 호환성

- `ExecuteStatement` request에서 Flink 1.20.4가 지원하지 않는 `executionTimeout` field를
  생략한다.
- `Config.ExecutionTimeout`과 `ExecuteOptions.ExecutionTimeout`은 제출부터 결과 수집까지의
  전체 client-side context deadline으로 적용한다.
- `ExecuteAndWait`, `StreamResults`, `ExecuteStream`은 실행 제한을 REST payload로 전달하지
  않고 Go context로 집행한다.
- 기본 `ExecutionTimeout`을 사용해도 더 이상 timeout 미지원으로 인한 HTTP 500이 발생하지
  않는다.

### Session 구성 timeout 호환성

- `ConfigureSession`도 양수 `executionTimeout` wire field를 전송하지 않는다.
- method의 `executionTimeout` 인자는 동기 configure 요청의 client-side context 제한으로
  적용한다.
- SQL Gateway가 요청을 처리하는 동안 caller context 또는 제한 시간이 끝나면 기존 context
  오류 체계를 통해 호출자에게 전달한다.

### 공개 API 호환성

- 기존 공개 type, field와 method를 제거하지 않아 source compatibility를 유지한다.
- `ExecuteStatementRequest.ExecutionTimeout`은 기존 코드의 compile 호환성을 위해 남겨 두지만
  Flink 1.20.4 REST payload에는 반영하지 않는다.
- 저수준 `ExecuteStatement` 제출 자체의 제한은 caller context 또는 `Config.RequestTimeout`을
  사용한다. 전체 operation 실행 제한이 필요하면 `ExecuteOptions.ExecutionTimeout`을 사용한다.

## 동작 변경

| 구분 | v0.1.2 | v0.1.3 |
| --- | --- | --- |
| statement REST `executionTimeout` | 기본값 `30000` 전송 | field 생략 |
| configure-session REST `executionTimeout` | 양수 millisecond 전송 | field 생략 |
| 고수준 실행 제한 | context와 REST field에 함께 적용 | context에만 적용 |
| Flink 1.20.4 기본 실행 | HTTP 500 가능 | 정상 operation handle 수신 |

## 업그레이드 시 확인사항

- `ExecuteAndWait`, `StreamResults`와 `ExecuteStream` 사용자는 호출 코드를 변경할 필요가 없다.
- `ExecuteStatementRequest.ExecutionTimeout`이 Gateway의 server-side timeout을 활성화한다고
  가정한 코드는 caller context 또는 고수준 실행 API로 전환해야 한다.
- 실제 transport 단절, 불완전한 response, HTTP 408·429 또는 5xx에서 반환되는
  `ErrExecutionOutcomeUnknown` 정책은 변경되지 않았다. 이 오류를 받은 statement를 자동으로
  재제출하지 말고 Gateway operation 또는 Flink Job 생성 여부를 먼저 확인해야 한다.
- `RequestTimeout`은 개별 HTTP 요청, `ExecutionTimeout`은 고수준 operation 전체 수명주기를
  제한하므로 운영 환경에 맞게 별도로 설정한다.

## 검증 결과

Go 1.26.5와 mock SQL Gateway 환경에서 다음 검증을 완료했다.

- Flink 1.20.4 동작을 모사해 `executionTimeout` field가 있으면 HTTP 500을 반환하는 회귀 테스트
- 기본 `Config.ExecutionTimeout`과 명시적 `ExecuteStatementRequest.ExecutionTimeout`을 사용해도
  statement request에서 wire field가 생략되는지 확인
- `configure-session` request에서도 동일한 wire field가 생략되는지 확인
- `go test ./...` 통과
- `go vet ./...` 통과
- integration build tag를 포함한 test compile 통과

실제 SQL Gateway integration test는 `FLINK_SQL_GATEWAY_URL`이 설정된 릴리스 환경에서 다시
실행해야 한다.

## 알려진 제한

- Flink 1.20.4 SQL Gateway 자체는 양수 REST `executionTimeout`을 지원하지 않는다.
- 실제 Gateway에서 response가 유실된 경우 operation handle을 복구하는 idempotency key 또는
  statement 조회 API는 제공되지 않는다.
- integration test 실행에는 별도로 기동한 Flink 1.20.4 SQL Gateway가 필요하다.
- Windows race detector는 C compiler `gcc`가 있는 환경에서 별도로 실행해야 한다.
