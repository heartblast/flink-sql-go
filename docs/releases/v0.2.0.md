# flink-sql-go v0.2.0 — Multi-Flink Support

- 라이브러리 버전: `v0.2.0`
- 릴리스 상태: 정식 릴리스
- 릴리스 날짜: `2026-07-30`
- 직접 검증한 Apache Flink patch: `1.20.4`
- 기본 SQL Gateway REST API: `v3`
- 기준 Go 버전: `1.26.5`

## 개요

v0.2.0은 하나의 Go module과 기존 공개 import 경로에서 여러 Flink release line을 표현하고 선택할 수 있도록 호환성 계층을 도입한다. Flink 제품 release와 SQL Gateway REST API 버전을 분리하고, 공통 client 위에 release profile과 capability를 적용한다.

라이브러리 release는 더 이상 Flink patch 하나에 종속되지 않는다. `compatibility.yaml`이 release line, 직접 검증 patch, REST API와 wire quirk의 canonical source이며 build는 동일한 데이터로 `compatibility.json`을 생성한다.

## Flink 호환성

| Flink release | 상태 | 직접 검증 patch | 표현 가능한 REST API | Stable | 비고 |
| --- | --- | --- | --- | --- | --- |
| `1.20.x` | maintenance | `1.20.4` | `v1`, `v2`, `v3` | `v3` | wire `executionTimeout` 미사용 |
| `2.0.x` | experimental | 없음 | `v1`~`v4` | `v3` | 실제 Gateway 검증 전 |
| `2.1.x` | experimental | 없음 | `v1`~`v4` | `v3` | 실제 Gateway 검증 전 |
| `2.2.x` | experimental | 없음 | `v1`~`v4` | `v3` | 실제 Gateway 검증 전 |
| `2.3.x` | experimental | 없음 | `v1`~`v4` | `v3` | 실제 Gateway 검증 전 |

experimental은 profile과 protocol 경계를 구현했다는 뜻이며 운영 호환성 보장을 뜻하지 않는다. 2.x의 `testedVersions`은 실제 contract test가 완료될 때까지 비어 있다. 표의 REST API는 client가 구조적으로 표현하는 범위이며 모든 endpoint를 실제 서버에서 검증했다는 주장이 아니다.

Flink 1.20.4에서는 양수 REST `executionTimeout`을 보내지 않고 기존과 같이 client-side context 제한만 적용한다. 2.x profile은 wire field를 사용할 수 있도록 capability를 분리했지만 실제 server 검증이 남아 있다.

## 주요 변경사항

- `ReleaseLine`, 지원 상태, `Capabilities`와 release registry 추가
- `CompatibilityMode`의 auto 및 명시적 release 선택 지원
- Stable, Highest, Explicit REST API 정책 추가
- `/info`와 `/api_versions`을 이용한 lazy 자동 감지
- 공통 profile과 server 광고 API의 교집합 검증
- schema 2의 API별 exact endpoint descriptor와 release capability 교집합
- Flink 2.3 v3 Materialized Table refresh 및 v4 Application Mode Script 배포 helper
- 기능별 outcome-unknown typed error와 SQL/Script/option redaction
- Flink 2.3 v1 포함 `executionTimeout` wire 및 SQL pass-through 검증
- manifest와 runtime registry의 protocol/release 일치를 확인하는 contract test
- release line별 fixture와 실제 Gateway test를 분리할 수 있는 CI 구조
- 산출물 이름에서 `-flink-<patch>` suffix 제거
- build-info에 전체 `supportedFlinkReleaseLines` 기록

## 공개 API와 하위 호환성

module과 공개 import 경로는 유지된다.

```text
github.com/heartblast/flink-sql-go
github.com/heartblast/flink-sql-go/flinksqlgateway
github.com/heartblast/flink-sql-go/flinkrest
```

`NewClient`, 기존 `Config` 필드, `Client` interface, session·operation·stream·decoder API와 `flinkrest` package를 제거하지 않는다. 외부 mock이 구현하는 기존 `Client` interface도 새 compatibility 메서드 때문에 깨지지 않도록 별도 확장 interface를 사용한다.

`SupportedFlinkVersion`과 `BuildInfo.FlinkVersion`은 `1.20.4` 값을 유지하지만 Deprecated다. 신규 코드는 `SupportedFlinkVersions()`, `CompatibilityMatrix()`과 `BuildInfo.SupportedFlinkReleaseLines`을 사용한다. 반환 slice와 중첩 compatibility 데이터는 내부 저장소와 공유하지 않는다.

`Config`, `Capabilities`, `BuildInfo`에는 새 export field가 추가됐다. 이 struct를 외부 package에서 unkeyed composite literal로 만들던 코드는 field 수 변경으로 compile 오류가 날 수 있으므로 field 이름을 지정한 keyed literal로 전환해야 한다.

## 동작 변경사항

기본 compatibility mode는 auto, API 정책은 Stable이다. `NewClient`는 네트워크를 호출하지 않으며 최초 versioned 요청 또는 명시적 compatibility 검사 때 감지한다. Explicit 정책에서 지정한 API를 server나 profile이 지원하지 않으면 fallback하지 않고 typed error를 반환한다.

기존 `APIVersion`을 명시하는 설정은 계속 사용할 수 있다. Flink 1.20.4 요청의 wire 형식과 client-side timeout 동작도 유지한다.

build의 `-FlinkVersion` parameter와 `SUPPORTED_FLINK_VERSION` override는 제거됐다. library artifact 하나가 전체 compatibility matrix를 나타내며 특정 test server 정보는 build metadata가 아니라 integration 환경변수로 전달한다.

## 업그레이드

```bash
go get github.com/heartblast/flink-sql-go@v0.2.0
```

기존 1.20.4 호출자는 설정을 바꾸지 않아도 되지만, 호환성 선택을 고정하려면 `CompatibilityMode`와 API 정책을 명시한다. 자체 build pipeline에서 `-FlinkVersion` 또는 `SUPPORTED_FLINK_VERSION`을 사용했다면 해당 옵션을 제거하고 `compatibility.yaml`과 생성된 compatibility JSON을 사용한다.

## 검증 범위

- Flink version parsing과 release line 선택
- 지원하지 않는 release와 공통 API 부재 typed error
- Stable, Highest, Explicit API 선택
- manifest와 runtime registry의 field·slice 일치
- capability snapshot의 깊은 복사
- Flink 1.20.4 `executionTimeout` wire 생략 회귀
- 기존 session, operation, paging, stream과 decoder unit test
- integration build tag compile
- `go vet ./...`과 module 정합성 검사
- `build.ps1` 전체 검증과 취약점 검사 통과

Flink 1.20.4는 기존 `compatibility.yaml`의 직접 검증 기록과 maintenance baseline을 유지한다. 실제 Gateway contract workflow matrix에도 1.20.4만 포함하지만, 이번 v0.2.0 준비 환경에는 repository endpoint secret이 없어 workflow를 재실행하지 않았다. 따라서 이번 릴리스에서 새로 직접 검증한 Flink patch는 없다. 2.0.x~2.3.x 실제 Gateway test도 수행하지 않았으며, 해당 계열은 experimental 상태다.

## 알려진 제한사항

- 2.x patch별 실제 Gateway response fixture와 장시간 통합 검증이 남아 있다.
- API v4의 Deploy Script는 구현됐지만 그 밖의 모든 v4 전용 endpoint를 지원한다는 의미는 아니다.
- 자동 감지는 `/info`가 반환한 parse 가능한 제품 버전과 `/api_versions` 응답을 요구한다.
- experimental profile의 capability는 upstream protocol 분석에 따른 구현 경계이며 운영 보증이 아니다.
- SBOM과 provenance는 이번 필수 산출물에 포함되지 않는다.
