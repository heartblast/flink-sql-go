# flink-sql-go v0.1.0 릴리스 노트

- 릴리스 버전: `v0.1.0`
- 지원 Apache Flink 버전: `1.20.4`
- 지원 SQL Gateway REST API: `v1`, `v2`, `v3`
- 기준 Go 버전: `1.26.5`
- 릴리스 예정일: 2026-07-24

## 개요

`v0.1.0`은 Apache Flink 1.20.4 SQL Gateway와 JobManager REST API를 Go 애플리케이션에서 사용할 수 있게 하는 첫 정식 릴리스다. JDBC, JVM, GraalVM, CGO, `database/sql` 없이 Go 표준 `net/http`를 사용하며 런타임 외부 Go 패키지 의존성이 없다.

세션과 SQL Operation, Flink Job의 lifecycle을 분리하고, 비멱등 SQL 요청의 중복 실행 방지와 bounded result 처리, 명시적인 자원 정리를 기본 정책으로 제공한다.

## 주요 기능

### SQL Gateway REST Client

- `/info`, `/api_versions` 조회 및 선택한 API version의 lazy 검증
- 세션 생성, 구성 조회, heartbeat, 종료
- v2 이상 configure-session 및 SQL completion
- SQL 제출과 Operation 상태 조회, 취소, 종료
- `NOT_READY` → `PAYLOAD` → `EOS` 결과 paging
- JSON 및 v2 이상 PLAIN_TEXT row format
- INSERT, UPDATE_BEFORE, UPDATE_AFTER, DELETE RowKind 보존
- context timeout/취소와 행 수, poll 횟수, 응답 크기 제한

### 실행 안정성과 결과 처리

- bounded 수집형 `ExecuteAndWait`
- channel 기반 `StreamResults`
- producer goroutine 없이 동작하는 iterator 기반 `ExecuteStream`
- 요청이 전달됐을 수 있지만 Operation handle을 받지 못한 경우를 구분하는 `ErrExecutionOutcomeUnknown`
- 원래 오류와 cancel/close cleanup 오류를 함께 보존하는 `ExecutionError`
- 중복 호출에 안전한 stream, session, client `Close`

### 세션 관리

- heartbeat와 건강 상태를 관리하는 `ManagedSession`
- 동일 세션의 SQL 실행 순서를 보장하는 `SerializedSession`
- Properties와 setup SQL을 명시적으로 재생하는 `SessionRecipe`
- recipe 실패 시 진행 범위와 실패 index 반환
- 실패한 recipe의 세션 종료 또는 명시적 유지 옵션

세션 만료 시 자동 세션 재생성이나 SQL 자동 replay는 수행하지 않는다.

### 타입과 메타데이터

- BOOLEAN, 정수, 부동소수점, 문자열 타입 decoder
- 정밀도 손실 없이 문자열을 보존하는 DECIMAL 타입
- DATE, TIME, TIMESTAMP, TIMESTAMP_LTZ 의미 구분
- BINARY, VARBINARY, ARRAY, MAP, ROW 변환
- 알 수 없는 미래 타입의 raw JSON 보존
- SQL NULL을 별도 상태로 반환하는 `RowAccessor`
- `SHOW`, `DESCRIBE`, `EXPLAIN PLAN FOR` 기반 Metadata Helper
- backtick과 Unicode를 포함한 Flink identifier escaping
- API version 문자열 비교를 대체하는 Capability API

### Changelog Materializer

별도 `flinksqlgateway/changelog` 패키지에서 Flink changelog를 현재 table snapshot으로 변환한다.

- 단일 및 복합 Primary Key
- INSERT, UPDATE_BEFORE, UPDATE_AFTER, DELETE 적용
- update 순서 검증
- 최대 메모리 행 수 제한과 임의 eviction 금지
- stable insertion order와 deep-copy snapshot

### Flink Job REST Client

별도 `flinkrest` 패키지에서 다음 JobManager lifecycle API를 제공한다.

- Job 조회 및 상태 조회
- Job cancel
- stop-with-savepoint
- Job exception과 checkpoint 조회
- Job plan 조회

SQL Gateway Operation cancel은 Flink Job cancel을 의미하지 않으며 두 기능은 자동 연결되지 않는다.

### 보안과 관측성

- SQL 제출 POST 등 비멱등 요청 자동 재시도 금지
- same-origin `nextResultUri` 검증으로 SSRF와 인증 header 유출 방어
- SQL 원문, 인증 header, URL query string을 기본 오류와 Observer에서 제외
- 주입 가능한 `StatementValidator`, `Observer`, `LifecycleObserver`
- 사용자 제공 HTTP client/header 및 transport 소유권 설정

## 중요한 동작 정책

- 기본 `Row.Fields`는 `json.RawMessage`이며 `row.WithColumns(...)`를 호출할 때만 타입 변환한다.
- 중복 컬럼명은 첫 번째 컬럼을 사용하고 SQL NULL은 별도 boolean 값으로 구분한다.
- SQL 제출 결과가 불명확하면 자동 재실행하지 않고 `ErrExecutionOutcomeUnknown`을 반환한다.
- 알 수 없는 미래 API version의 capability는 지원을 추측하지 않고 `false`로 반환한다.
- Metadata Helper는 별도 세션을 자동 생성하지 않고 전달받은 세션의 현재 catalog/database를 사용한다.
- Materializer는 Primary Key와 결과 column metadata가 모두 명시된 경우에만 생성된다.

## 알려진 제한

- 실제 Flink 1.20.4 환경의 장시간 streaming, session expiry, API version별 contract matrix 검증은 별도로 필요하다.
- trusted reverse proxy의 외부 origin rewrite를 허용하는 NextResultURI resolver는 포함하지 않는다.
- 전체 fuzz suite는 아직 포함하지 않는다.
- Linux build script와 cross-platform CI, SBOM, provenance 자동 생성은 포함하지 않는다.
- Windows race detector는 C compiler가 있는 환경에서 별도로 실행해야 한다.
- 인증 방식과 사용자 권한 정책은 상위 서비스가 제공해야 한다.

## 공개 전 필수 확인

현재 Git 원격 저장소는 `github.com/heartblast/flink-sql-go`지만 `go.mod`의 module path는 아직 초기값인 `flink-sql-go`다. 공개 module release 전에 module path와 저장소 내부 import를 `github.com/heartblast/flink-sql-go`로 변경하고 `go mod tidy` 및 전체 검증을 다시 수행해야 한다.

최종 게시 순서:

1. module path와 내부 import 경로 수정
2. 모든 변경사항 commit 후 clean worktree 확인
3. `v0.1.0` annotated tag 생성
4. Go 1.26.5 환경에서 `.\build.ps1 -Release` 실행
5. 생성된 ZIP, build-info, 취약점 보고서, `.sha256`을 release asset으로 첨부
