# flink-sql-go v0.1.4 릴리스 노트

- 릴리스 버전: `v0.1.4`
- 지원 Apache Flink 버전: `1.20.4`
- 지원 SQL Gateway REST API: `v1`, `v2`, `v3`
- 기준 Go 버전: `1.26.5`
- 릴리스 예정일: 2026-07-27

## 개요

`v0.1.4`는 SELECT 결과에서 실제 SQL NULL과 누락되거나 손상된 field를 명확히 구분하는 patch
release다. 정상적인 Flink SQL Gateway 응답의 non-NULL 값은 기존에도 `Row.Fields`에 보존됐지만,
빈 `json.RawMessage`가 decoding 오류 없이 `nil`로 반환되고 column 수보다 field가 적은 행이
고수준 결과 수집을 통과할 수 있었다. 호출 코드가 오류와 NULL을 구분하지 않으면 이 상태가 SQL
NULL처럼 관측될 수 있었다.

이번 릴리스는 JSON literal `null`만 SQL NULL로 인정한다. 누락·빈 JSON field, 유효하지 않은
JSON과 schema/행 field 개수 불일치는 명시적인 오류로 반환하며, 여러 결과 page에 분리된 schema를
수집형과 stream형 실행 경로에서 모두 이어서 검증한다.

## 주요 변경사항

### SQL NULL 판정 강화

- JSON literal `null`만 `RowAccessor`의 `isNull=true`로 반환한다.
- 빈 `json.RawMessage`와 유효하지 않은 JSON field는 NULL로 변환하지 않고 decoding 오류로
  반환한다.
- `Raw`, `RawAt`, `Value`, `ValueAt`이 동일한 field 유효성 규칙을 적용한다.
- 알 수 없는 미래 logical type은 기존처럼 유효한 원본 JSON을 보존한다.

### 결과 schema와 행 검증

- `ExecuteAndWait`가 각 행의 field 수와 수집한 column schema의 개수를 비교한다.
- `StreamResults`와 `ExecuteStream`도 동일한 검증을 적용한다.
- column metadata와 row data가 서로 다른 page에 도착하면 앞 page의 schema를 유지해 다음 행에
  적용한다.
- schema 없이 data가 도착하거나 field가 누락된 protocol 응답은 조용히 결과에 포함하지 않는다.

### 문서와 회귀 테스트

- `ExecutionResult.Columns`는 schema metadata이고 실제 SELECT 값은 `Rows[*].Fields`에 있다는
  점을 README에 명시했다.
- `LogicalType.Nullable`은 현재 값의 NULL 여부가 아니라 column의 NULL 허용 여부임을 설명했다.
- JSON, PLAIN_TEXT, 실제 SQL NULL, 여러 page와 누락 field를 포함하는 contract test를 추가했다.
- 분석과 수정에 사용한 재현 절차를 `prompt_management` 문서로 남겼다.

## 동작 변경

| 구분 | v0.1.3 | v0.1.4 |
| --- | --- | --- |
| 실제 SQL NULL | JSON `null`을 `isNull=true`로 반환 | 동일 |
| 빈 JSON field | `(nil, nil)`로 decoding 가능 | 명시적인 decoding 오류 |
| column/field 개수 불일치 | 고수준 수집을 통과할 수 있음 | 결과 protocol 오류 |
| page별 schema | 최초 schema 수집 | 최초 schema 유지 후 각 page 행 검증 |
| 정상 non-NULL 값 | `Row.Fields`에 원본 보존 | 동일 |

## 공개 API 호환성

- 공개 type, field, method를 제거하거나 이름을 변경하지 않았다.
- 정상적인 Flink 1.20.4 응답의 반환 타입과 값은 변경되지 않는다.
- 기존에 성공으로 처리되던 malformed result만 오류를 반환하므로 오류 처리 경로를 확인해야 한다.
- `Row.Fields`의 `json.RawMessage` 표현과 알 수 없는 logical type의 원본 보존 정책은 유지한다.

## 업그레이드 시 확인사항

`ExecutionResult.Columns`와 `LogicalType.Nullable`을 실제 행 값으로 해석하지 않아야 한다. 현재 행의
값은 schema를 연결한 accessor로 읽고, 오류를 먼저 확인한 다음 NULL 여부를 처리한다.

```go
accessor := result.Rows[0].WithColumns(result.Columns, nil)
value, isNull, err := accessor.String("column_name")
if err != nil {
    return err
}
if isNull {
    // 실제 SQL NULL
}
_ = value
```

## 검증 결과

Go 1.26.5와 mock SQL Gateway 환경에서 다음 항목을 검증했다.

- 공식 SQL Gateway response shape의 JSON/PLAIN_TEXT non-NULL 값 보존
- JSON literal `null`의 `(value=nil, isNull=true)` 반환
- 빈 JSON field와 column/field 개수 불일치의 오류 반환
- 여러 page에 분리된 column metadata와 row data 연결
- `go test ./...` 통과
- `go vet ./...` 통과
- `git diff --check` 통과

실제 SQL Gateway integration test는 `FLINK_SQL_GATEWAY_URL`이 설정된 릴리스 환경에서 다시
실행해야 한다. Windows race detector는 C compiler와 CGO가 준비된 환경에서 별도로 실행해야
한다.

## 알려진 제한

- 실제 Gateway URL이 없는 개발 환경에서는 mock contract test만 실행된다.
- schema와 data가 분리된 page는 앞서 유효한 schema를 수신한 경우에만 처리할 수 있다.
- Flink 1.20.4 SQL Gateway 자체의 REST `executionTimeout` 제한은 `v0.1.3`과 동일하다.
